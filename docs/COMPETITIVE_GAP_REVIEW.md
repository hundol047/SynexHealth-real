# 경쟁 앱 대비 차별성·부족 기능 점검 (2026-11-21)

비교 대상 유형: 체성분 측정 앱(InBody 앱), 종합 헬스 앱(Samsung Health·Apple 건강), 근력 운동 기록·추천 앱(Fitbod·Hevy·Strong).
아래 기능 존재 여부는 이 저장소 소스 기준이며, 경쟁 앱 기능은 일반적인 공개 기능 범주로 비교했습니다.

## Synex Health의 차별점 (유지)

| 영역 | Synex Health | 일반 경쟁 앱 |
|---|---|---|
| 측정 → 운동 연결 | 부위별 체성분(팔·몸통·다리) 기반 루틴 생성, 재측정 시 루틴 자동 재검토 | 체성분 앱은 측정 표시 위주, 운동 앱은 체성분 미사용 |
| 시각화 | 측정값 기반 3D 인체 morph, 비교군 평균 오버레이, Before/After | 2D 그래프 위주 |
| 학교 건강센터 | 학교 선택, 동의 기반 상담사 조회, 상담 메모 | 기관 연동 없음 |
| 운동 시범 | 74종 자체 3D 시범, 카메라 자세 피드백(실험적), 템포·음성 안내 | 영상/GIF 위주 |
| 안전 | 통증 기록 시 자동 증량 차단, 문진 차단, 미검증 수치 명시 | 대체로 없음 |
| 개인 모드 | 서버 없이 로컬 암호화 저장·암호 백업 | 계정·클라우드 필수 |

## 부족했던 부분과 이번 수정

| 부족 기능 | 경쟁 앱 현황 | 조치 |
|---|---|---|
| 개인 최고 기록(PR) | Hevy·Strong·Fitbod 기본 제공 | **추가** — `/health/progress` "개인 최고 기록": 운동별 최고 중량, 맨몸 최고 횟수, 최근 갱신 표시. 준비 세트·통증 기록 세트·미래 날짜 제외 |
| 추정 1RM | Strong·Fitbod 제공 | **추가** — Epley 공식, 10회 이하 중량 세트만 계산, 참고값임을 명시 |
| 부위별 훈련량 | Fitbod 근육 회복/볼륨 표시 | **추가** — 상체·몸통·하체별 이번 주 본 세트와 이전 4주 주평균 |
| 측정 결과 ↔ 실제 훈련 연결 | 경쟁 앱에 없음 (차별 기능 강화) | **추가** — "측정 결과 ↔ 실제 훈련량": 최근 측정에서 기준 대비 90% 미만 부위의 훈련 비중이 30% 미만이면 루틴 확인 안내. 진단·처방이 아님을 명시 |

구현: `frontend/src/health/lib/trainingInsights.js`, `frontend/src/health/components/TrainingProgress.jsx`,
테스트 `frontend/tests/TrainingInsights.test.jsx`. 서버 모드와 개인(로컬) 모드 모두 동작합니다(로컬 기록은 운동 이름으로 카탈로그 부위를 찾습니다).

## 3차 개선: 운동 동작 전수 점검 (2026-11-21)

운동 74종 + 스트레칭 30종(총 104개)을 실제 렌더링과 같은 방식(운동복 표면 변형, 신발, 기구 형상)으로 전 구간 계산하고, 의심 동작은 화면으로 렌더링해 확인했습니다.

| 발견한 문제 | 수정 |
|---|---|
| 누워 한 무릎 안기·두 무릎 안기·누워 뒤 허벅지 늘리기: 엉덩관절이 약 150° 접혀 허벅지가 배·가슴을 관통, 손이 몸통을 뚫고 등 뒤로 나옴 | 엉덩관절·무릎 각도를 직접 지정(엉덩관절 최대 125°). 손은 무릎 바로 위 허벅지 뒤를 옆에서 받침 |
| 누운 스트레칭에서 바닥을 디딘 발의 신발이 세로로 서 있음(벽을 딛는 모양) | 디딘 발은 바닥에 평평하게, 들어 올린 발은 정강이에 직각으로 |
| 4자 스트레칭: 올린 발목이 허공의 고정 좌표에 놓이고 시작 자세에서 다리가 옆으로 누움 | 발목을 지지 다리 허벅지 위에 올리고, 시작 자세는 무릎을 세운 자세로 |
| 옆구리 늘리기·삼두·어깨 교차 스트레칭: 자세에 들어가고 나올 때 팔이 몸통·목을 관통(시작·유지 자세는 정상이라 정지 화면에서는 보이지 않음) | 팔이 옆 또는 앞으로 돌아 올라가도록 중간 경유 자세 추가 |
| 레그 익스텐션·시티드 레그 컬: 기계 회전축 봉이 양쪽 무릎을 관통 | 다리 바깥쪽의 짧은 허브 2개로 변경 |
| 시티드 레그 컬·랫풀다운: 허벅지 패드가 허벅지 안에 파묻힘 | 실제 허벅지 윗면 높이를 재서 그 위에 얹음 |
| 해머 컬·덤벨 컬: 팔을 내렸을 때 덤벨 머리가 허벅지와 겹침 | 내린 구간에서 전완을 바깥으로 벌림 |

재발 방지: `frontend/tests/MotionAudit.test.js`가 104개 전 동작에 대해 팔의 몸통·머리 관통(전환 구간 포함), 바닥·벽 통과, 관절 가동 범위, 팔다리 길이, 기구 패드·덤벨 위치를 검사합니다. 기하학적 검사이며 실제 사람의 운동 정확성이나 자세 인식 정확도를 검증하는 것은 아닙니다.

추가 편의 개선: 운동 기록 화면에 계획이 없을 때 「운동 계획 바로 만들기」 한 번으로 생성 후 바로 시작합니다(이전에는 운동 계획 화면으로 이동해 다시 눌러야 함).

## 4차 개선: 보안·개인정보 보호와 조작 (2026-11-21)

- 보안 헤더(CSP, 권한 정책 등), 운영 환경 API 문서 비공개, 오류 응답에서 입력 건강 수치 제거, 로그인 경로 요청 제한, 개인용 빌드 CSP 강화. 상세: [SECURITY_AND_PRIVACY.md](SECURITY_AND_PRIVACY.md).
- 입력 오류 시 "요청 실패 (422)" 대신 어떤 항목을 확인해야 하는지 표시합니다.
- 운동 기록 화면에 오늘의 운동 바로가기(완료 시 ✓ 표시)를 추가했습니다.

## 6차 개선: 동작 부드러움·자세 분석 요약·검토 반영 (2026-11-23)

- **동작:** 104개 동작의 프레임 간 속도 변화를 측정해 뚝 끊기는 지점을 찾았습니다. 스트레칭의 팔 경유 경로를 한 곡선으로 합치고, 팔다리가 완전히 펴질 때 한 프레임에 잠기던 것을 부드럽게 했으며, 아기 자세에서 무릎이 3cm 미끄러졌다 돌아오던 문제를 고쳤습니다. 해당 관절의 속도 급변(최고 속도 대비)은 0.86~1.59에서 0.45 미만으로 줄었습니다. 버드독의 좌우 전환과 런지 무릎(0.23~0.61)은 접지 정확도와 맞물려 그대로 두었습니다.
- **자세 분석 요약:** 촬영 후 결과에 반복 속도의 일정함, 움직임 범위가 끝까지 유지됐는지, 정면 촬영 시 좌우 관절 각도 차이, 분석 가능했던 구간 비율을 수치와 함께 "잘된 점 / 확인할 점"으로 표시합니다. 측정한 값의 요약이며 자세의 옳고 그름을 판정하지 않습니다. 반복 3회 미만이면 속도를, 4회 미만이면 범위를 말하지 않습니다.
- **넣지 않은 것 — 관절 좌표 떨림 필터:** One Euro 필터를 실제 분석 주기(150ms)로 시험했습니다. 정지 시 떨림은 줄지만 움직이는 동안 각도 오차가 2.6°에서 5.4°로 커졌고, 손해가 없는 설정에서는 이득이 움직일 때 5%, 정지 시 17%에 그쳐 적용하지 않았습니다.
- **검토 반영:** 기준 대비(%)를 비운 부위가 0%로 처리되던 문제, 같은 날짜 재입력 시 이전 기록을 쓰던 문제, 심사 계정 잠금을 누구나 걸 수 있던 문제, 개발용 API 문서가 CSP에 막히던 문제, 운동 바로가기 이동 문제를 고쳤습니다.

## 아직 남은 격차 (이번에 구현하지 않음)

- **수분·수면·단백질 간단 체크**: 건강 기록은 기기 암호화 저장소에만 두는 원칙이 있어, 저장 구조(문서 버전) 변경과 백업 호환 검토 후 추가해야 합니다.
- **식단·단백질 기록**: 경쟁 종합 헬스 앱은 제공. 체성분 목표와 연결하면 차별성이 크지만, 영양 권고는 전문가 검토가 필요해 보류했습니다.
- **수면·심박 등 웨어러블 지표**: HealthKit/Health Connect 연결 구조는 있으나, 화면에서 수면 데이터를 활용하지 않습니다.
- **다크 모드**: 전용 테마가 없습니다. CSS에 직접 쓴 색상이 613곳이라 한 번에 바꾸면 화면이 깨질 위험이 커서, 색상 토큰 정리 후 진행하는 것이 안전합니다.
- **소셜·챌린지**: 친구·학교 단위 챌린지 기능이 없습니다(학교 연동과 결합할 수 있음).
- **홈 화면 위젯·워치 앱**: 없음.
- 기존 문서의 외부 검증 항목(실기기, 실제 사람 자세 정확도, 스토어 결제, 학교 API)은 여전히 미완료입니다. [PERSONAL_RELEASE_READINESS.md](PERSONAL_RELEASE_READINESS.md) 참고.
